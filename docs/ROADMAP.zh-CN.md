# LeafVault 里程碑与验收

日期：2026-10-20。当前处于 M0 规划阶段，M1–M4 尚未开始。时间为一位熟悉相关技术的全职开发者的初步人周估算，包含基本测试与修复，不是交付日期；实际投入与实验结果尚未确定。

## 1 阶段安排

| 阶段 | 主要交付 | 前置条件 | 初步工作量 |
| --- | --- | --- | --- |
| M0 产品规划 | 公开仓库、许可、范围、架构候选、同步设计、验收标准 | 明确免费开源与自托管目标 | 当前文档工作 |
| M1 关键技术实验 | 中文编辑样例、文件恢复实验、兼容扫描、搜索对比、技术决定记录 | 开始实施时选定 M1 范围 | 1–2 人周 |
| M2 macOS 本地 Alpha | 可安装并日用的单机版本，完成编辑、查找、链接与恢复 | M1 的编辑与保存问题解决 | 3–5 人周 |
| M3 自托管同步 Alpha | 客户端同步、单节点服务、部署文档、冲突与备份恢复 | M2 数据可靠性验收通过 | 3–5 人周 |

M1–M4 合计约 10–17 人周。M2 可作为早期体验点，累计约 4–7 人周；它不包含自托管同步。移动端、端到端加密、实时协作、插件生态和大规模托管运维不计入此估算。发现框架或协议需要更换时重新估算。

不为填满时间表而扩大功能。每一阶段用下面的门槛决定是否继续。

## 3 M1 关键技术实验

| 实验 | 输入与操作 | 验收产物 |
| --- | --- | --- |
| 中文编辑与即时预览 | 拼音连续输入、选词、撤销/重做、粘贴、组合输入时切换文件、长文滚动 | 可重复步骤、屏幕录制、失败列表；不得丢字或破坏选区 |
| 保存与恢复 | 在写日志、替换文件、提交本地状态等边界终止进程；模拟磁盘满、权限失败、外部改动 | 每个故障点的预期和实际哈希；确认已保存内容可恢复 |
| Markdown 兼容 | 合成库含中文路径、同名文件、标题锚点、frontmatter、未知语法、附件 | 支持矩阵、只扫描不改写证明、歧义提示与回归样例 |
| 搜索 | 中文单字/双字/长句、中英混合、标题与路径过滤 | 正确性结果与延迟、索引大小；明确采用的分词与回退策略 |
| 平台与分发 | macOS 原生窗口、剪贴板、文件访问、辅助功能和打包样例 | 支持系统与架构候选、实际开销、替代方案比较 |

先使用合成库，再在获得授权后使用真实笔记副本。技术实验分支可以包含最小代码，但本次 M0 不创建这些实现。

## 4 M2 本地日用门槛

完成“新建/打开库 → 编辑 → 插图 → 双链 → 搜索 → 关闭重开 → 恢复误删”的完整流程。

必须核验：

- 首次扫描不改变原库正文、附件及既有配置。
- 切换笔记、退出和重启不会丢失已确认保存的内容。
- 中文输入场景全部通过；快捷键与鼠标操作结果一致。
- 重命名只修改真实指向目标的链接；失败后能继续或恢复。
- 外部编辑发生在未保存缓冲区存在期间，两份内容均可找回。
- 删除、历史恢复与本地索引重建可重复执行。
- 真正使用 7 天并保留问题记录；阻断数据丢失、不可恢复及输入损坏问题。

## 5 性能测量计划

目标基线为 Apple Silicon M1、16 GB 内存、SSD；实际测试须记录芯片、系统版本、电源状态、应用提交号与数据集校验和。Windows/Linux 各自建立基线，不沿用 macOS 数字。

合成基准库拟包含 10,000 篇笔记、约 100 MiB 正文及 1,000 个独立附件；附件总量固定并记录。另加 1 MiB 长文与密集链接样例。正式测试前冻结样例生成方法。

| 指标 | 初始目标 | 测量方式 |
| --- | --- | --- |
| 索引完成后的应用启动到可输入 | p95 ≤ 2 秒 | 进程退出后重启 30 次；保留索引，并说明操作系统文件缓存条件 |
| 常见笔记切换到可输入 | p95 ≤ 150 毫秒 | 固定笔记集合，至少 100 次 |
| 首批全文搜索结果 | p95 ≤ 300 毫秒 | 包括中文短词在内的固定查询集，至少 100 次 |
| 编辑响应 | 常规操作无超过 100 毫秒的主线程阻塞 | 输入与滚动轨迹，单列长文结果 |
| 首次索引与资源开销 | 先测量，再定预算 | 独立记录时间、峰值内存、空闲 CPU、磁盘占用及实际安装包大小 |

这些是拟定门槛，没有任何实测结果。响应速度必须同时满足正确性；不能通过漏搜或跳过落盘满足数字。

## 6 M3 同步与恢复门槛

两台桌面设备必须覆盖：

| 场景 | 必须成立的结果 |
| --- | --- |
| 离线各自编辑后重连 | 两份修改可找回，冲突稳定呈现 |
| 服务端提交成功但响应丢失 | 重试同一操作不会重复创建文件或版本 |
| 上传中断与服务重启 | 不发布缺失附件的版本，可恢复传输 |
| 编辑与删除并发 | 编辑内容被保留，删除意图可识别 |
| 重命名、同名与大小写差异 | 不覆盖错误文件；不可表示的路径明确报错 |
| 长期离线设备带过期游标重连 | 重新对账，不自动复活远端已删除内容 |
| 服务端从旧备份恢复 | 客户端识别同步世代变化，保留本地独有数据 |
| 撤销设备 | 后续请求被拒绝，其他设备仍正常 |
| 磁盘满与数据库/内容损坏 | 明确失败，不把未持久化操作报告为成功 |
| 两个笔记库的对象请求 | 没有权限时无法跨库读取内容 |

在固定数据集上检查正常顺序和故障注入两类运行。比较当前文件、冲突副本、历史与删除状态；每个案例须给出期望结果。重放至少两轮确认幂等。

在空白主机上完成一次真实备份恢复，核对内容哈希和附件可读性。首次部署体验由未参与开发的人执行；文档假设和准备时间单独记录。

## 7 M4 发布门槛

- 每个声明支持的系统与 CPU 架构都有安装、启动、文件权限、中文输入、更新和卸载检查。
- Windows/Linux 与 macOS 混合同步，验证非法文件名、大小写和 Unicode 规范化差异。
- 以 Windows 11 x64、Ubuntu LTS x64 为初始验证候选，实施时核实版本支持与依赖；其他发行版不自动视为支持。
- 至少 3 名试用者在 7 天内完成核心任务；记录需要协助的位置和未解决问题。
- 文档列出确切支持平台、已知限制、同步信任模型、恢复路径和对应版本。
- 发布源码、构建说明、依赖许可清单、校验和及镜像版本；签名、公证和更新渠道按实际配置说明。
- 自动更新有校验与失败恢复路径；数据库升级前自动备份。
- 数据丢失、恢复失败、鉴权绕过和严重输入错误没有未解决的发布阻断项。

平台证书、签名、公证及分发账号可能产生维护费用。官方软件免费政策不依赖承诺这些外部资源零成本。
