# LeafVault 产品计划

日期：2026-10-20。状态：规划草案；本文功能尚未实现。

LeafVault 面向希望长期保有笔记、重视桌面写作体验、愿意自行管理同步的个人用户。目标是交付一套客户端和同步服务完整开源、官方软件免费、无需依赖项目方云服务的笔记工具。

第一阶段用一个完整的日常工作流验证价值：打开笔记文件夹，写作并插入附件，连接已有内容，搜索，再次打开并恢复历史。多设备同步在本地可靠性成立后加入。

## 1 产品原则

| 原则 | 具体政策 |
| --- | --- |
| 完整开源 | 第一方客户端、同步服务、协议说明、构建与部署文件都公开 |
| 官方软件免费 | 个人及商业使用免费，无高级版功能锁、许可证激活或设备数量付费墙 |
| 本地可独立工作 | 不注册项目方账号，不联网，也能编辑、搜索和恢复本地历史 |
| 普通文件可迁移 | 正文保存为 Markdown，附件保持普通文件，索引可以重建 |
| 同步可自托管 | 用户控制服务器和数据目录，可以迁移到另一台服务器 |
| 体验优先 | 先解决输入、搜索、保存、恢复，再扩展功能数量 |
| 隐私明确 | 无广告、无行为遥测；诊断包由用户查看并主动分享 |

采用 AGPL-3.0-only。它覆盖相应的分发和修改后网络服务源码义务；它允许商业用途，也不保证任何人的托管服务免费。官方免费政策与许可证各自承担不同作用，具体授权以 [LICENSE](../LICENSE) 为准。[许可证说明](https://choosealicense.com/licenses/agpl-3.0/)

可持续维护优先依靠赞助、捐赠及可选的部署支持。若以后提供托管服务，收费对象只能是托管与服务，软件仍保留功能完整的免费自托管版本。首阶段不建设付费系统。

## 2 首批用户与价值假设

首批用户是使用 Markdown 管理学习、研究、项目与日常笔记的人；其中一部分已经有 Obsidian 文件夹，一部分希望第一次就得到简洁的使用体验。

待验证的核心假设：这些用户愿意为了“全部开源、普通 Markdown、自托管同步、中文编辑舒服”的组合迁移，并愿意承受首版功能较少的限制。这是项目选择，尚不是市场验证结果。

建议邀请 3–5 名不同习惯的用户完成同一组任务：建立笔记、插图、双链、找回旧内容、外部编辑、恢复误删、接入第二台设备。记录完成率、耗时、需要帮助的位置及继续使用的意愿。联系人招募与访谈尚未执行。

## 3 主要使用流程

### 第一次打开

首页只提供“新建笔记库”和“打开已有文件夹”。本地流程不出现注册、购买、模型配置或服务器配置。

打开现有库时先扫描内容，展示不支持的格式和命名冲突。首次试用建议创建副本；仅扫描不得改写正文。用户打开并编辑具体文件后，才产生对应写入。

### 日常写作

默认布局为左侧文件树、中间编辑器、可收起的右侧大纲或反向链接。初始只展开必要面板，工具栏保持简洁。

编辑器提供即时预览和源码模式，支持标题、列表、任务列表、代码块、表格及图片。即时预览必须保持选区、输入法组合状态和撤销顺序稳定。表格先提供可靠的 Markdown 编辑与渲染，复杂表格操作后续扩展。

新建笔记后立即获得输入焦点；键盘可以完成切换笔记、搜索、插入链接和关闭面板。粘贴图片时给出保存反馈，名称冲突自动分配新文件名，不覆盖已有附件。

### 找回内容

快捷切换优先匹配标题和路径；全文搜索支持中英文混合、中文短词、标签及路径过滤。结果提供上下文片段，点击后定位到匹配位置。

输入 `[[` 显示已有笔记候选，也可创建新笔记。同名笔记展示所在路径。反向链接区分明确引用与普通文本提及，首版只实现明确引用。

### 保存与恢复

保存状态使用可理解的文本：保存中、已保存、保存失败。“已保存”只代表本地内容成功持久化，“已同步”单独表示服务器确认的状态。

保存失败保留编辑缓冲区，允许重试或另存为。外部修改与当前未保存编辑发生冲突时保留两份内容，显示比较与恢复入口。删除进入可恢复流程；历史恢复本身产生新版本。

### 启用自托管同步

同步是设置中的可选功能。用户输入服务地址并完成设备配对后，选择笔记库。首次连接展示上传、下载、同名冲突和删除的预览，任何批量覆盖都不能悄悄执行。

同步页解释当前状态、待传项目、冲突、最近成功时间，以及用户能够采取的操作。内部游标、操作 ID 等留在诊断信息中。

## 4 功能优先级

| 阶段 | 纳入内容 | 完成意义 |
| --- | --- | --- |
| 桌面 Alpha | 文件树、标签页、Markdown、图片、双链、反链、搜索、快捷切换、撤销、保存状态、本地历史 | 可以在一个平台完成日常写作 |
| 同步 Alpha | 一个用户的多个设备、多笔记库、身份验证、断线重试、冲突副本、删除记录、历史与备份恢复 | 可以用自己的服务器可靠同步 |
| 桌面 Beta | Windows/Linux 验证、安装升级、键盘与无障碍检查、性能优化、迁移报告 | 可以邀请外部用户持续使用 |
| 后续候选 | 移动端、端到端加密、WebDAV/S3 适配、模板、日记、公式、局部图谱 | 按实测需求逐项选择 |

完整插件运行时、多人实时协作、白板、复杂数据库视图、发布平台、AI 工作流均不进入上述首版范围。常见语法可以先保留源码，不能因为暂时无法渲染而删除内容。

移动端是重要的后续方向；桌面多设备同步 Beta 不意味着已经完成手机与电脑同步。

## 5 体验验收

以下均是目标，后续按 [验收方案](ROADMAP.zh-CN.md) 记录实际设备、系统版本和测试结果。

- macOS 中文拼音输入、连续选词、中英混输、组合输入期间撤销及切换笔记，不丢字、不重复提交、不跳光标。
- 每次保存失败可见；重启后能够找到已显示保存成功的内容。
- 本地写作核心流程全程可用键盘完成；焦点可见，控件有可访问名称。
- 明暗主题下正文、选中状态和错误信息可辨认；正文宽度及字号可调，放大至 200% 后主要操作仍可达。
- 用户能区分“本地已保存”“等待同步”“发生冲突”，不用理解协议即可恢复内容。
- 测试库中，打开文件夹仅扫描时正文与附件逐文件哈希不变；未编辑文件保持字节一致。
- 完整日用测试持续 7 天，保留每日核验与异常记录；阻断数据丢失、无法恢复和输入损坏问题。

## 6 交付方式与边界

先做 macOS，然后逐平台验证 Windows、Linux。macOS 的具体最低系统版本和 Intel 支持需由 M1 实验确定；没有实机验证的平台不会标为已支持。

第一版自托管目标为单节点 Linux 主机或兼容 NAS，一个应用容器加持久化目录，外部通过现有反向代理提供 HTTPS。数据库与附件都能备份并恢复到空白实例。初期不要求 Kubernetes、Redis 或外部数据库。

首个同步版本信任服务器管理员，管理员能够访问服务端内容；HTTPS 保护传输，不等同于端到端加密。加密能力及更详细边界见 [同步方案](SYNC.zh-CN.md)。

## 7 建议推进顺序

先完成编辑器与文件可靠性的技术实验，再实现单机日用版本。单机验收通过后开始同步协议与恢复实验，随后接入完整界面和多平台打包。

每个阶段都应有可供别人复现的结果。遇到数据可靠性或中文输入问题，优先修复，不通过堆叠功能绕过。详细依赖、估算与停止条件见 [路线图](ROADMAP.zh-CN.md)。
